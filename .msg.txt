Stop a mode change from reverting to the saved value

The practice mode could not be changed once a session had been saved.
load depended on mode, so picking another mode rebuilt it and re-ran
the session effect; when a session was on disk that effect called restore(),
which set the mode back to the stored one. The dropdown sprang back on
every attempt.

The mode is now read from a ref, so it is out of the dependency list and a
mode change no longer restarts anything. The session effect is guarded to run
once per mount, with the book, scope and size selectors rebuilding
explicitly instead of relying on that effect.

Three DOM tests cover the case: switch after a restore, switch twice, and
switch across a question.
