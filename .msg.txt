Explain installer failures instead of showing a file error

Installing over a running copy failed with "无法打开要写入的文件", which
says nothing about the cause. A pre-install hook now opens the binary that
is about to be replaced, and when that fails, tells the user to end
lexiflow.exe in Task Manager and retry.

The check is a local FileOpen on $INSTDIR rather than a process lookup. An
earlier version ran tasklist through nsExec, which hung the installer on this
machine and also matched a stale process left by a crashed parent, so a
process that could never be killed blocked every install.

Verified: a clean install succeeds, an install over a running copy is
refused with the message instead of failing mid-copy, and the same install
succeeds once the application is closed.
